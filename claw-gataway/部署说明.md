# claw-gataway 部署参数说明

本文档说明 `claw-gataway/k8s` 目录下一键部署脚本及相关配置中的全部参数。部署入口为 **`k8s/install.sh`**（推荐）；`k8s/deploy.sh` 为精简版，参数子集相同但不含 SeaweedFS 存储与部分 vLLM 高级选项。

## 目录结构

```
claw-gataway/
├── DEPLOYMENT.md          # 本文档（部署参数）
├── IMAGES.md              # 镜像列表
└── k8s/
    ├── install.sh         # 主部署脚本（K8s + vLLM + 可选 SeaweedFS）
    ├── deploy.sh          # 精简部署脚本
    ├── cleanup.sh         # 清理脚本
    ├── namespace.yaml
    ├── postgres.yaml
    ├── redis.yaml
    ├── new-api.yaml
    ├── configmap.yaml
    ├── chart-helm/        # vLLM Helm Chart
    └── storage/
        ├── config.sh      # SeaweedFS 宿主机存储参数
        └── install.sh     # SeaweedFS 安装脚本
```

## 快速开始

```bash
# 1. 编辑 k8s/install.sh 顶部「必填配置」
# 2. 确保模型文件已放入 VLLM_MODEL_HOST_PATH（若 DEPLOY_VLLM=true）
# 3. 执行部署
cd claw-gataway/k8s
./install.sh

# 仅安装 SeaweedFS 存储（宿主机 systemd，需 root）
sudo ./install.sh storage
```

部署完成后脚本会输出 Web 地址、管理员账号、API Token 及模型调用示例。

完整容器镜像清单见 **[IMAGES.md](./IMAGES.md)**。

## 一、install.sh 主部署参数

所有参数定义在 `k8s/install.sh` 文件顶部「必填配置」区块，部署前按环境修改。

### 1.1 Kubernetes 基础

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `NAMESPACE` | `new-api` | Kubernetes 命名空间，所有组件部署于此 |

### 1.2 容器镜像

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `NEW_API_IMAGE` | `registry-public.lenovo.com/newapi/new-api:new-api-v1` | New API 应用镜像 |
| `POSTGRES_IMAGE` | `registry-public.lenovo.com/newapi/postgres:15` | PostgreSQL 15 镜像 |
| `REDIS_IMAGE` | `registry-public.lenovo.com/newapi/redis:latest` | Redis 镜像 |

### 1.3 New API 初始化与安全

| 参数 | 默认值 | 约束 | 说明 |
|------|--------|------|------|
| `INIT_ADMIN_USERNAME` | `admin` | ≤ 12 字符 | 首次部署自动创建的管理员用户名，跳过 Web 向导 |
| `INIT_ADMIN_PASSWORD` | `ChangeMe123456` | ≥ 8 字符 | 管理员密码 |
| `INIT_WEB_ACCESS_TOKEN` | （见脚本） | ≤ 32 字符 | Web API 鉴权 Token，用于 `Authorization` 请求头 |
| `INIT_USAGE_MODE` | `external` | `external` \| `self` \| `demo` | 使用模式：对外运营 / 自用 / 演示站点 |
| `SESSION_SECRET` | （见脚本） | ≥ 32 字符 | Session 加密密钥，生产环境务必修改 |

**API 调用示例（管理员）：**

```bash
curl -H "Authorization: ${INIT_WEB_ACCESS_TOKEN}" \
     -H "New-Api-User: 1" \
     http://<节点IP>:${NODE_PORT}/api/user/self
```

### 1.4 PostgreSQL

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `POSTGRES_USER` | `root` | 数据库用户名 |
| `POSTGRES_PASSWORD` | `123456` | 数据库密码 |
| `POSTGRES_DB` | `new-api` | 数据库名 |
| `PG_DATA_HOST_PATH` | `/data/pgdata` | PostgreSQL 数据 hostPath（节点本机目录） |

脚本会自动生成连接串：

```
SQL_DSN=postgresql://${POSTGRES_USER}:${POSTGRES_PASSWORD}@postgres:5432/${POSTGRES_DB}
```

### 1.5 Redis

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `REDIS_PASSWORD` | `123456` | Redis 密码 |

连接串：

```
REDIS_CONN_STRING=redis://:${REDIS_PASSWORD}@redis:6379
```

### 1.6 网络与存储路径

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `NODE_PORT` | `30080` | New API NodePort 对外端口（范围 30000–32767） |
| `DATA_HOST_PATH` | `/data` | New API 应用数据 hostPath |
| `PG_DATA_HOST_PATH` | `/data/pgdata` | PostgreSQL 数据 hostPath |

部署前脚本会 `mkdir -p` 创建上述目录（及 vLLM 模型目录）。

## 二、vLLM 模型服务参数

通过 Helm Chart `k8s/chart-helm` 部署。`install.sh` 会将下列变量映射为 `helm upgrade --install` 的 `--set` 参数。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `DEPLOY_VLLM` | `true` | 是否部署 vLLM；`false` 则跳过第 4 步 |
| `VLLM_RELEASE_NAME` | `vllm` | Helm Release 名称 |
| `VLLM_MODEL_NAME` | `Qwen3.5-35B-A3B-FP8` | 对外暴露的模型名（`--served-model-name`） |
| `VLLM_MODEL_HOST_PATH` | `/data/models/${VLLM_MODEL_NAME}` | 节点本地模型权重目录（hostPath 挂载） |
| `VLLM_IMAGE_REPO` | `registry-public.lenovo.com/newapi/new-api` | vLLM 镜像仓库 |
| `VLLM_IMAGE_TAG` | `vllmopenai0.22` | vLLM 镜像标签（Qwen3.5 MoE 需 vLLM ≥ 0.17.1） |
| `VLLM_EXTRA_ARGS_JSON` | 见脚本 | 额外 vLLM 启动参数，**JSON 数组**，每项对应一个 CLI 参数 |
| `VLLM_GPU_ENABLED` | `auto` | GPU 模式：`auto`（自动检测）\| `true` \| `false` |
| `VLLM_GPU_RUNTIME_CLASS` | `""` | 可选 RuntimeClass 名（`kubectl get runtimeclass` 查看） |

### 2.1 VLLM_EXTRA_ARGS_JSON 示例

当前默认配置（Qwen3.5 MoE）：

```json
[
  "--tensor-parallel-size", "2",
  "--enable-expert-parallel",
  "--language-model-only",
  "--reasoning-parser", "qwen3",
  "--max-model-len", "8192",
  "--gpu-memory-utilization", "0.90"
]
```

修改时须保持合法 JSON 数组格式；脚本通过 `--set-json extraArgs=...` 传入 Helm。

### 2.2 GPU 自动调度逻辑

| `VLLM_GPU_ENABLED` | 行为 |
|--------------------|------|
| `auto` | 检测节点 `nvidia.com/gpu` 资源；有 GPU 则 `gpu.count=2`，无则降级为 CPU 资源限制 |
| `true` | 强制 GPU 模式，`gpu.count=2` |
| `false` | CPU 模式：`requests 2 CPU / 8Gi`，`limits 4 CPU / 16Gi` |

若 `VLLM_GPU_RUNTIME_CLASS` 非空且启用 GPU，会额外设置 `gpu.runtimeClassName`。

### 2.3 部署前准备

- 将完整模型文件（含 `config.json`、权重等）放入 `VLLM_MODEL_HOST_PATH`
- 集群需已安装 `kubectl`、`helm`
- GPU 场景需节点已配置 NVIDIA 设备插件

## 三、vLLM 自动注册与定价

部署 vLLM 后，可通过 New API REST API 自动创建渠道、Token 及模型倍率。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `AUTO_REGISTER_VLLM` | `true` | 是否在 vLLM 就绪后自动注册渠道与 Token |
| `VLLM_CHANNEL_NAME` | `vllm` | 渠道名称 |
| `VLLM_CHANNEL_BASE_URL` | `http://vllm-service.new-api.svc.cluster.local` | 渠道上游地址（集群内 Service） |
| `VLLM_CHANNEL_KEY` | `vllm` | 渠道 Key（OpenAI 兼容上游通常填占位符） |
| `VLLM_TOKEN_NAME` | `auto-vllm` | 自动创建的 API Token 名称 |
| `NEW_API_ROOT_USER_ID` | `1` | 调用管理 API 时 `New-Api-User` 头中的用户 ID |
| `AUTO_SETUP_MODEL_PRICING` | `true` | 是否自动设置模型倍率 |
| `VLLM_MODEL_RATIO` | `1` | `ModelRatio` 与 `CompletionRatio` 默认值 |

注册成功后脚本输出 `sk-<token>`，可直接用于 OpenAI 兼容接口：

```bash
curl -H "Authorization: Bearer sk-<token>" \
     -H "Content-Type: application/json" \
     -d '{"model":"<VLLM_MODEL_NAME>","messages":[{"role":"user","content":"你好"}]}' \
     http://<节点IP>:${NODE_PORT}/v1/chat/completions
```

自动注册为幂等操作：已存在同名渠道/Token 时会更新必要字段而非重复创建。

## 四、SeaweedFS 存储参数

SeaweedFS 在**宿主机**以 Docker + systemd 运行，与 K8s / vLLM **独立**（vLLM 仍使用本地 hostPath 模型目录）。

| 参数（install.sh） | 默认值 | 说明 |
|--------------------|--------|------|
| `DEPLOY_STORAGE` | `true` | 完整部署时是否在 K8s 步骤后安装 SeaweedFS（需 root） |

详细参数在 **`k8s/storage/config.sh`**，支持环境变量覆盖：

### 4.1 节点与集群

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `STORAGE_NODE_IP` | `0.0.0.0` | 本机绑定 IP；多节点时每台填各自 IP |
| `STORAGE_MASTER_PEERS` | `0.0.0.0:7200` | Master 集群 peers，逗号分隔 `host:port` |
| `STORAGE_DATA_ROOT` | `/data/server/s3` | 数据根目录 |
| `STORAGE_COMPONENTS` | `master,volume,filer,s3` | 本节点启用的组件，可选含 `wrapper` |

**多节点示例：** 三台机器 peers 一致，例如：

```
STORAGE_MASTER_PEERS=10.199.117.2:7200,10.199.117.3:7200,10.199.117.4:7200
```

### 4.2 镜像

| 参数 | 默认值 |
|------|--------|
| `STORAGE_SEAWEEDFS_IMAGE` | `registry-public.lenovo.com/newapi/new-api:seaweedfs430` |
| `STORAGE_WRAPPER_IMAGE` | `registry-public.lenovo.com/earth_system/seaweedfs-wrapper:3.71` |

### 4.3 Volume 配置

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `STORAGE_VOLUME_MAX` | `1536` | Volume 最大数量 |
| `STORAGE_VOLUME_DATA_CENTER` | `xclaw1` | 数据中心标识 |
| `STORAGE_VOLUME_RACK` | `rack1` | Rack 标识 |
| `STORAGE_VOLUME_SIZE_LIMIT_MB` | `4096` | 单 Volume 大小上限（MB） |
| `STORAGE_DEFAULT_REPLICATION` | `000` | 默认副本策略 |

### 4.4 端口

| 参数 | 默认端口 | 组件 |
|------|----------|------|
| `STORAGE_MASTER_PORT` | 7200 | Master |
| `STORAGE_VOLUME_PORT` | 7201 | Volume |
| `STORAGE_FILER_PORT` | 7202 | Filer |
| `STORAGE_S3_PORT` | 7203 | S3 Gateway |
| `STORAGE_WRAPPER_PORT` | 7206 | Wrapper |

### 4.5 安全与 S3 密钥

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `STORAGE_JWT_FILER_KEY` | （见 config.sh） | Filer JWT 密钥 |
| `STORAGE_WRAPPER_SECRET_KEY` | （见 config.sh） | Wrapper 密钥 |
| `STORAGE_S3_ACCESS_KEY` | `admin` | S3 Access Key（写入 config.json） |
| `STORAGE_S3_SECRET_KEY` | `ChangeMeS3SecretKey` | S3 Secret Key |
| `STORAGE_GRPC_TLS_AUTO_CERT` | `true` | 无证书时自动生成 gRPC mTLS 自签名证书 |
| `STORAGE_GRPC_TLS_REGENERATE` | `false` | 设为 `true` 强制重新生成证书（修复 handshake 失败） |

Filer 元数据使用本地 **leveldb2**（`templates/filer.toml`，目录 `/data/filerldb2`）。

### 4.6 单独安装存储

```bash
sudo ./install.sh storage
# 或
sudo bash k8s/storage/install.sh
```

## 五、Helm Chart 扩展参数（chart-helm）

`install.sh` 仅覆盖部分 Chart 值。如需深度定制，可直接使用 Helm 并参考 `k8s/chart-helm/values.yaml`。

| Chart 键 | install.sh 映射 | 说明 |
|----------|-----------------|------|
| `servedModelName` | `VLLM_MODEL_NAME` | 对外模型名 |
| `image.repository` | `VLLM_IMAGE_REPO` | 镜像仓库 |
| `image.tag` | `VLLM_IMAGE_TAG` | 镜像标签 |
| `trustRemoteCode` | 固定 `true` | 加载自定义架构模型 |
| `extraArgs` | `VLLM_EXTRA_ARGS_JSON` | 额外 CLI 参数 |
| `extraInit.storage.hostPath` | `VLLM_MODEL_HOST_PATH` | 本地模型目录 |
| `gpu.enabled` | `VLLM_GPU_ENABLED` 检测结果 | 是否启用 GPU |
| `gpu.count` | GPU 时固定 `2` | GPU 数量 |
| `gpu.runtimeClassName` | `VLLM_GPU_RUNTIME_CLASS` | RuntimeClass |

### 5.1 未由 install.sh 设置但常用的 Chart 参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `replicaCount` | `1` | 副本数 |
| `resources` | GPU: 8–16 CPU, 32–64Gi | 容器资源（CPU 模式由脚本覆盖） |
| `autoscaling.enabled` | `false` | HPA 自动扩缩 |
| `extraInit.storage.type` | `local` | `local`（hostPath）或 `pvc` |
| `extraInit.modelDownload.enabled` | `false` | 从 S3 下载模型（需配置 S3  endpoint） |
| `readinessProbe.initialDelaySeconds` | `120` | 就绪探针初始延迟 |
| `livenessProbe.initialDelaySeconds` | `300` | 存活探针初始延迟 |

**手动 Helm 部署示例：**

```bash
helm upgrade --install vllm ./chart-helm -n new-api \
  --set servedModelName=Qwen3.5-35B-A3B-FP8 \
  --set image.repository=registry-public.lenovo.com/newapi/new-api \
  --set image.tag=vllmopenai0.22 \
  --set-json 'extraArgs=["--tensor-parallel-size","2"]' \
  --set extraInit.storage.hostPath=/data/models/Qwen3.5-35B-A3B-FP8 \
  --set gpu.enabled=true \
  --set gpu.count=2
```

## 六、部署流程与步骤

`install.sh` 按以下顺序执行（步骤总数随选项变化）：

```
┌─────────────────────────────────────────────────────────┐
│  validate_config → 创建命名空间 → 创建 Secret/ConfigMap   │
├─────────────────────────────────────────────────────────┤
│  [1] PostgreSQL (StatefulSet)                           │
│  [2] Redis (Deployment)                                 │
│  [3] New API (Deployment + NodePort Service)            │
│  [4] vLLM (Helm, 若 DEPLOY_VLLM=true)                   │
│  [5] 自动注册渠道/Token/定价 (若 AUTO_REGISTER_VLLM)    │
│  [+] SeaweedFS 宿主机安装 (若 DEPLOY_STORAGE=true)      │
└─────────────────────────────────────────────────────────┘
```

| 选项组合 | 总步骤数 |
|----------|----------|
| 仅 K8s 核心（无 vLLM） | 3 |
| K8s + vLLM | 4 |
| K8s + vLLM + 自动注册 | 5 |

## 七、参数校验规则

脚本启动时会执行 `validate_config`：

| 参数 | 规则 |
|------|------|
| `INIT_ADMIN_USERNAME` | 长度 ≤ 12 |
| `INIT_ADMIN_PASSWORD` | 长度 ≥ 8 |
| `INIT_WEB_ACCESS_TOKEN` | 长度 ≤ 32 |
| `SESSION_SECRET` | 长度 ≥ 32 |
| `INIT_USAGE_MODE` | 必须为 `external`、`self` 或 `demo` |

## 八、清理脚本参数

`k8s/cleanup.sh` 使用固定命名空间与路径（与 deploy/install 保持一致）：

| 用法 | 说明 |
|------|------|

## 九、常见配置场景

### 9.1 仅部署 New API 平台（不含 vLLM 与存储）

```bash
DEPLOY_VLLM="false"
```

## 十、install.sh 与 deploy.sh 差异

| 能力 | install.sh | deploy.sh |
|------|------------|-----------|
| SeaweedFS 存储 | 支持（`DEPLOY_STORAGE`） | 不支持 |
| vLLM 镜像/额外参数 | `VLLM_IMAGE_*`、`VLLM_EXTRA_ARGS_JSON` | 使用 Chart 默认镜像 |
| 模型定价自动配置 | `AUTO_SETUP_MODEL_PRICING` | 不支持 |
| Token 模型限制 | 自动限制为 vLLM 模型 | 不限制模型 |
| GPU 数量（检测到 GPU） | `gpu.count=2` | `gpu.count=1` |
| 渠道 Base URL | 无 `/v1` 后缀 | 含 `/v1` 后缀 |

**推荐使用 `install.sh` 作为统一部署入口。**
